# 评估：把 BlackMyth-NeZha v1.4.0（Three.js）的好东西移植到天工版 nezha-boss

> 玩法轨 · 2026-11-06。依据：仓库 main（v1.4.0，2026-11-02）全部代码与 `docs/PROMPT_ENGINEERING.md`、`docs/OPEN_SOURCE_COMBAT_ASSETS.md`；对照 nezha-boss M4（已通过）与设计文档 / 已拍板会议。

## 结论
**可行，但要「挑着搬、按天工的写法重写」，不能整体复制。**
- 两边引擎完全不同（Three.js 场景树 vs 天工 ECS + 插件），代码不能直接粘贴；但 v1.4.0 里最值钱的是**设计方法和调好的参数**（弹簧系数、状态浮动表、飘带参数、配乐编排、验收标准），这些和引擎无关，可以原样带过来。
- 有几样和老板已拍板的设计冲突（跳跃、小怪前置关、敖丙 Boss、悟空线），不能直接搬，要开会定。
- 两个硬约束：① 绘制命令 ≤ 13（每加一条飘带、一个小怪都是额外绘制，要合并成一张网格才行）；② 设计文档由主窗口改、拍板后才动。

## 分三批
### 第一批：可以直接搬，不冲突，收益大
| 内容 | v1.4.0 里是什么 | 搬过来怎么做 | 改动量 |
|---|---|---|---|
| 背景音乐 + 音效 | 五声音阶程序化配乐：太鼓、二胡、钹、低音持续音；探索 / 战斗 / 二阶段三种模式；混响 + 压限；整套招式音效（锣等） | 我们的音频本来就在网页层用 Web Audio，几乎可原样搬；接到一局流程（入场 / 战斗 / 转阶段 / 胜利） | 小 |
| 悬浮的「惯性」 | 二阶弹簧驱动：加速前倾、刹车后仰并下沉回弹、转弯向内侧倾、14 种状态各自的离地高度 / 起伏 | 只搬「整体」那一层（前倾、侧倾、急停下沉、状态浮动表），高度和幅度沿用我们拍板的 1.15 m / ±15 cm | 小～中 |
| 更多飘带 | 一套通用飘带：两端固定或单端、随时间翻卷扭转、往身后拖；哪吒身上 5 条 + 枪缨 6 缕 | 我们已有红绫（单条）；把翻卷、双端固定搬来，加绕臂长绫、发带、枪缨；**全部合成一张网格**守住绘制预算 | 中 |
| 完美闪避奖励「灵息」 | 回 30 气力、解除力竭、2.5 秒回气 ×2；气力条青光脉冲、浮字「+30 气力」 | 状态机加一个计时；HUD 加脉冲和浮字 | 小（会影响难度，需老板点头） |
| 发版门禁 + 主观评审表 | 发版前自动跑验收、任一阻断项失败就不发；8 维主观评审（剪影、色彩、层次、材质、动态、打击、预兆、UI），任一 < 3 分不交 | 我们已有构建版真实键鼠验收脚本；补一个总入口和评审表，以后发版前必跑 | 小 |

### 第二批：值得搬，但要先定方向
| 内容 | 问题 |
|---|---|
| 带关节的程序化哪吒（髋 / 躯干 / 头 / 大小腿，双丫髻、荷叶裙、莲瓣、乾坤圈） | 能根治现在「刚体占位很僵」的问题（骨盆滞后、腿部双摆、头部预判都要关节）；但和资产轨 M5 的正式模型方案重叠，要定「先用程序化关节模型过渡」还是「等正式模型」 |
| 开源素材调研（KayKit CC0 等） | 直接给 M5 选素材用；但都是 Q 版风格，和写实东方神话不搭 |
| 残影改淡青、灵气粒子汇聚等反馈 | 好看，但「青色」要和预警色、龙身色的规则对一下（方向板） |

### 第三批：和已拍板设计冲突，不建议直接搬
| 内容 | 冲突点 |
|---|---|
| 跳跃 / 空翻 / 跳劈 | 我们的设计没有跳；加了会改变躲龙招的方式，M2～M4 的平衡要重来 |
| 小怪前置关（巡海夜叉、攻击令牌、清怪开水门） | 我们是单场 Boss 战 + 峡道；加小怪是范围变化，且吃绘制预算 |
| 敖丙当 Boss | 我们的叙事里敖丙已死（龙王的「我儿」），Boss 是东海龙王 |
| 悟空 / 黑风山 | 不在本项目范围 |
| Gerstner 海面、栈道、镇海台 | 我们的战场在海沟漩涡（水下），用不上；远景龙宫轮廓、盘龙柱可做 M5 场景素材参考 |
| 攻击消耗气力 | 老板 M2 定了攻击不耗气力，保持不变 |

## 建议
先做第一批（配乐音效、悬浮惯性、多条飘带、发版门禁；「灵息」等老板点头），作为 M5 的第一项；第二批放进 M5 开工评审 / 音频会一起定；第三批不搬，除非老板要改范围。

- 第二批：直接搬（带关节的程序化哪吒、灵息、开源素材调研结论、淡青残影与灵气粒子）。
- 第三批：**悟空线不要；Boss 由东海龙王换成东海三太子·敖丙，模型用 v1.4.0 的敖丙（冰龙太子），招式直接用 v1.4.0 的，场景也替换为 v1.4.0 的。**
