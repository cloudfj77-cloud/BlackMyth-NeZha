## 一、整体计划逻辑

先定设计，再写代码；先跑通玩法，再打磨视听；每一步都要验收后才往下走。

```
阶段 A 设计（当前）                阶段 B 开发（M1→M5）                 阶段 C 发布
需求梳理 → 角色设计会 → 专项会议 →  每个里程碑：实现 → build →          中英封面 → 造化发布检查
           （老板拍板）  （老板拍板）  构建版本地预览真实输入验收 →       → 上传 → 分享链接
                                      老板试玩 → 修改
```

**阶段 A：设计会议**。每场会议都按同一套流程进行：主持人准备简报，各角色先独立发言，再交叉讨论，最后由制作人整理决议草案，老板拍板。拍板之后才能改文档。
