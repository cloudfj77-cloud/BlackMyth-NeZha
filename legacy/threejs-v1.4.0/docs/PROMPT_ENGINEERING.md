# 《黑神话：哪吒》Prompt 工程（完整版 v2）

> 用途：把本项目的全部设计决策沉淀为**可复用、可验收**的提示词。任何人（或任何 AI）拿这份文档，都能复现同样的角色、动作、怪物、Boss、关卡，并用同一套验收标准判断"能不能交付"。
>
> 结构：**0 总控 → 1 调研结论 → 2 角色（哪吒）→ 3 悬浮动作系统 → 4 小怪 → 5 Boss → 6 关卡/场景 → 7 战斗手感 → 8 自循环验收系统 → 9 迭代协议 → 附录（可直接复制的子 Prompt）**

## 0. 总控 Prompt（Master Prompt）

```
你是一个由「主美 + 动作设计 + 关卡设计 + 战斗策划 + 技术美术 + QA」组成的 3A 动作游戏小组。
目标：做一款写实东方神话风格的 3D 第三人称动作 Boss 战网页游戏《黑神话：哪吒》，对标《黑神话：悟空》的品质要求。

硬约束：
1. 运行环境：浏览器 + Three.js（WebGL），无外部美术资源，所有模型/贴图/音频程序化生成，可离线运行。
2. 主角哪吒「全程悬浮、永不触地」，并且「每个动作状态都有不同的浮动形态」。
3. 关卡结构必须是「前置关卡（小怪）→ 检查点 → 关卡门 → Boss 场」，不能一上来就打 Boss。
4. 所有敌人攻击都必须有「动作前摇 + 地面预警 + 声音」三重预兆，前摇 ≥ 0.45s。
5. 翻滚闪避必须能在任何时刻取消任何动作（阵亡除外），无硬直。
6. 交付前必须运行「自循环验收系统」，任一阻断级用例失败 → 禁止交付，修复后重跑，直到全部通过。

工作方式（每一轮）：调研 → 设计（写出可量化参数）→ 实现 → 运行验收 → 看截图做主观评审 → 修复 → 再验收 → 通过后才发版。
输出：代码 + 验收报告（含实测数值和截图）+ 更新日志。不要只说"已完成"，要给出实测证据。
```

## 1. 调研结论（设计依据）

### 1.1 哪吒形象来源
| 来源 | 关键信息 | 本作采用 |
| --- | --- | --- |
| 《封神演义》 | 莲花化身；乾坤圈、混天绫随灵珠子转世；太乙真人再造后赐火尖枪、风火轮、金砖；三头八臂 | 莲花化身（荷叶裙、莲瓣肩甲、太乙莲台检查点）、乾坤圈、混天绫、风火轮 |
| 《西游记》 | 三头六臂；斩妖剑、砍妖刀、缚妖索、降妖杵、绣球、火轮儿 | 预留"三头六臂"作为后续大招 |
| 现代经典形象 | 脚踏风火轮、手提长枪、腰间荷叶裙、身披混天绫；双丫髻、眉心火焰印 | 全部采用；按用户要求武器改为**红缨枪** |
| 敖丙（2019/2025 动画） | 冰蓝主色、龙角、龙鳞铠甲，与哪吒红金形成冷暖对立 | Boss 采用冰龙太子设定 |
| 东海龙宫/陈塘关 | 陈塘关古镇、海边关隘；龙宫取敦煌藻井、夔龙纹、马远《水图》层波叠浪 | 海岸栈道、龙柱、镇海台、远景龙宫 |

### 1.2 悬浮/飞行角色的动作设计方法（行业做法）
- **物理驱动倾斜**：前倾角 = atan(水平加速度 / g)；加速前倾、刹车后仰；转弯按向心加速度向弯内侧倾（bank）。没有倾斜的角色"像在轨道上滑"。
- **重叠与跟随（Disney 12 法则第 5 条）**：躯干领先、骨盆滞后、腿部双摆滞后、头部提前转向（预判）；停下后飘带/衣物继续摆动再静止。
- **永不静止**：多频率正弦叠加（如 1 : 1.618），避免机械规律感；但"浮动"不能变成"弹跳"（峰峰值控制在 3~16cm）。
- **离地读感**：悬浮必须有"接触提示"——地面光斑/阴影随高度变大变淡；否则玩家看不出离地。
- **弹簧-阻尼**：所有次级运动用二阶弹簧（频率 f、阻尼 ζ）驱动，惯性力作为外力输入，而不是直接设角度。

### 1.3 Boss / 怪物设计原则（类魂游戏共识）
- **可读预兆**：每招有独特起手剪影 + 地面范围 + 音效；同一信号含义始终一致，不"背刺"玩家。
- **节奏**：攻击窗 → 惩罚窗（大招后摇 ≥ 0.9s）→ 恢复窗；像对话一样一来一回。
- **阶段演进而非替换**：二阶段在一阶段招式上"加尾巴"（第三刀加震地、横扫加二段），并伴随外观/音乐/场景变化。
- **公平**：每次死亡玩家都应知道"我该怎么躲"。
- **小怪群体规则**：攻击令牌（同一时刻最多 1 只出手），其余绕圈施压；体型/剪影与 Boss 明显区分。

### 1.4 《黑神话：悟空》品质参照（可在网页上近似的部分）
实景扫描古建、体积雾、动态全局光照、毛发、民族乐器配乐。网页端可近似：**大气透视雾**、**IBL 环境光**、**ACES 色调映射**、**软阴影**、**程序化 PBR 材质**、**物理飘带**、**五声音阶 + 民乐音色**。

```

## 3. 悬浮动作系统 Prompt（本轮核心）

```
设计一套程序化悬浮运动层（HoverMotion），叠加在常规骨骼姿势之上，使哪吒在任何状态下都悬空、且各状态浮动形态不同。

一、输入（每帧）：当前状态、水平速度向量、竖直速度、朝向、玩家输入方向。
二、输出：离地高度、前倾 pitch、侧倾 roll、骨盆滞后 yaw、头部预判 yaw、大腿/小腿/侧摆、手臂拖尾。
三、全部用二阶弹簧（频率 f，阻尼 ζ）驱动：
    高度 f=1.8 ζ=0.55；pitch f=2.2 ζ=0.5；roll f=2.0 ζ=0.45；骨盆 f=2.6；头 f=4.0 ζ=0.7；
    大腿 f=2.4 ζ=0.4；小腿 f=3.2 ζ=0.35（由大腿角速度驱动 → 双摆鞭梢感）。
四、物理驱动：
    pitch 目标 = atan(前向加速度/g)×0.35 + min(0.14, 速度×0.014) + 状态前倾×0.5，限幅 [-0.35, 0.38]
    roll 目标  = atan((横向加速度×0.5 + 角速度×速度×0.6)/g)，限幅 ±0.5
    骨盆 yaw   = 弹簧(0, 外力 = -角加速度×0.35)，躯干反向补偿 80%（胸领先、髋滞后）
    头 yaw     = 弹簧(输入方向-朝向)×0.6，限幅 ±0.6（提前看向要去的方向）
    大腿       = 弹簧(收腿量×0.25, 外力 = -前向加速度×1.4 - 竖直速度×1.5)
五、状态浮动表（hover=离地高度 m、bob=起伏幅度、freq=起伏频率 Hz、legs=收腿、lean=附加前倾）：
    待机 idle   0.58 / 0.065 / 0.5 / 0.35 / 0      —— 慢呼吸般漂浮，左右漂移
    移动 move   0.48 / 0.045 / 0.9 / 0.5  / 0.12
    疾奔 sprint 0.40 / 0.025 / 1.4 / 0.85 / 0.30  —— 贴低疾飞，腿后收，身体前倾
    轻击 attack 0.42 / 0.015 / 1.2 / 0.55 / 0.10
    重击 heavy  0.30 / 0.01  / 1.0 / 0.9  / 0.05  —— 下压出枪
    蓄力 charge 0.85 / 0.03  / 2.2 / 1.0  / -0.05 —— 升空蓄势、高频颤动
    施法 cast   0.95 / 0.05  / 1.6 / 0.6  / -0.08 —— 最高点结印
    饮酒 drink  0.62 / 0.05  / 0.7 / 0.4  / -0.04
    受击 hurt   0.38 / 0     / 0   / 0.6  / -0.30 —— 被打得后仰下沉
    翻滚/跳跃/跳劈/落地/阵亡 各有独立参数
    起伏 = bob×(0.7·sin(2πft) + 0.3·sin(2π·1.618ft + 1.3))；急停时额外下沉并回弹。
六、硬约束：每帧计算风火轮最低点，低于离地 0.12m 则整体上抬（翻滚、跳劈下砸都不例外）。
七、离地读感：脚下地面火光斑，随离地高度变大变淡、随速度变大。
八、腿部不做迈步循环（悬浮者不走路），只做收腿 + 惯性摆 + 左右错频小幅摆动。
```

**验收标准（量化）**
| 项 | 标准 |
| --- | --- |
| 待机离地（轮最低点） | > 0.30m |
| 待机起伏峰峰值 | 0.03 ~ 0.16m（漂浮而非弹跳） |
| 起步前倾 | > 0.04rad |
| 疾奔前倾 | 比待机大 0.1 以上，且 < 0.45rad（不趴下） |
| 疾奔离地 | 低于待机（贴低疾飞） |
| 转弯侧倾 | \|roll\| > 0.08rad |
| 蓄力离地 | 比待机高 0.08m 以上 |
| 混合高强度操作全程 | 最低点 > 0.02m（永不触地） |

## 7. 战斗手感 Prompt（两位角色共用）

```
键位：WASD 移动 / 鼠标视角 / 左键轻击（4 段）/ 右键按住蓄力（3 级）/ 空格翻滚 / Ctrl·F 跳跃 / Shift 按住疾奔 /
     R 锁定（优先 Boss，否则最近小怪）/ Q 葫芦（4 次）/ 1 法术（悟空定身术、哪吒混天绫·缚）/ B 血条位置。
取消规则：翻滚 > 一切（阵亡除外）；跳跃可取消攻击后摇/落地/翻滚；轻击可在翻滚后半段直接起手。
衔接：统一速度 + 重力物理；疾奔→翻滚→疾奔速度不断档；翻滚中跳 = 远跳；空中翻滚 = 空翻；空中左键 = 跳劈。
完美闪避：命中前 0.25s 内翻滚 → 无伤 + 慢动作 + 残影 + 回气力 + 法术冷却 -2s；0.2s 内连滚不判定（防乱按）。
气力：轻击/重击/翻滚/跳跃/疾奔消耗；停止高耗动作 0.85s 后恢复；>0 即可翻滚。

## 8. 自循环验收系统 Prompt（质量门禁）

```
建立一个「自动化 + 主观评审」双层验收回路，未通过不得交付。

A. 自动化层（qa/run.js，真实 Chrome 驱动）
   - 用"渲染帧数"而不是墙钟时间等待（低帧率环境下也能稳定测量）
   - 每条用例输出：PASS/FAIL、实测值、标准值、级别（阻断/警告）
   - 生成 qa/report/report.md、report.json 与关键截图
   - 任一阻断级失败 → 退出码 1 → scripts/release.sh 中止发版
B. 主观评审层（每轮必须逐张看截图，按下表打分，任一项 < 3 分即判定不通过并修复）
C. 循环：实现 → 跑 A → 看 B → 修复 → 再跑，直到 A 全绿且 B 全部 ≥ 3 分
```

## 9. 迭代协议（每次更新都按这个走）

```
1. 需求 → 写成可量化参数（如"更飘" → 起伏峰峰值、频率、弹簧阻尼的具体数值）
2. 先补验收用例（新功能没有用例 = 没有完成）
3. 实现
4. node qa/run.js → 阻断失败就修，直到全绿
5. 逐张看 qa/report/*.png，按 §8.2 打分，<3 分就修
6. scripts/release.sh <patch|minor|major> "说明"（脚本会再跑一次验收，不过不发）
7. 线上回归：打开 GitHub Pages 地址确认版本号与核心功能
```
